mosaics-targets — Multi-Survey Target Selection & Crossmatch Pipeline¶

mosaics-targets (uv run -m mosaics.cli.targets) executes the eight-stage target selection, photometric rescue, multi-survey crossmatch, homogenisation, and reporting pipeline over the declination sky-cell grid.

Key capabilities¶

  • Reads all survey roles, SQL queries, HATS paths, column maps, and photometric/spectroscopic systems from --config (default defs/full.yaml; production runs typically use defs/targets.yaml).

  • Stores intermediate sky-cell datasets under <output>/stores/ with append-only cell ledgers so re-running the same command resumes automatically from unfinished sky cells.

  • Writes <output>/targets_report.yaml and renders the mosaics-targets@1 scireport bundle (<output>/report/targets_report.scireport.zip), chapter-split Markdown (<output>/report/md/), and PDF (<output>/report/pdf/report.pdf).

Examples¶

$ uv run -m mosaics.cli.targets --config defs/targets.yaml -o ./targets_run --dec-range 0.0 1.0 --plan plan.yaml
$ uv run -m mosaics.cli.targets --config defs/targets.yaml -o ./targets_run --dec-range 0.0 1.0 --workers 8
$ uv run -m mosaics.cli.targets --config defs/targets.yaml -o ./targets_run --dec-range -5.0 5.0 --proxy http://127.0.0.1:8888

Entry points: mosaics-targets or uv run -m mosaics.cli.targets

Option / Argument

Default

Choices

Description

--output, -o OUTPUT

required

—

Directory the run writes into.

--config, -c FILE

None

—

Survey definitions entrypoint. Everything this run knows about a survey comes from the files it pulls in: which query extracts it, which table it crossmatches against, which passbands it measures through and how its brightnesses convert. Point it at a smaller entrypoint, or pass –survey, to run a subset of the surveys. Default: full.yaml under defs/, which is every survey.

--survey REF

None

—

Survey files to run on, replacing the entrypoint’s surveys:: library names or paths, .yaml optional, globs allowed (--survey surveys/ls11 surveys/wise). The entrypoint’s overrides: still apply.

--exclude-survey REF

None

—

Survey files to remove from the run, same syntax as –survey.

--overwrite

false

—

Rebuild artifacts that already exist instead of reusing them. Off by default: extraction is the expensive part of the run, and a re-run usually means “add a survey” or “widen the box”, not “start again”.

--overwrite-cache

false

—

Replace every sky-cell store this run reads – its rows and its ledger of finished and failed cells – and fetch it again. Not implied by –overwrite, which rebuilds the candidate table and the catalogue from the stores already on disk: that costs minutes and contacts no archive, refetching costs the hours the stores exist to avoid. Pass this when an archive has republished its data.

--no-report-pdf

true

—

Skip the PDF of the run report. The YAML, the sealed report bundle (report/targets_report.scireport.zip) and its Markdown, split by chapter (report/md/), are written either way; this only drops the PDF.

--store-dir STORE_DIR

None

—

Where each extraction and crossmatch keeps its rows: one Lance dataset per step, kept by HEALPix cell beside a ledger of finished and failed cells. A later run over a wider –ra-range or –dec-range fetches only the cells it does not have yet, and a run that crashed fetches only the cells it had not finished. Defaults to a “store” directory under –output. Nothing here is evicted; see –prune-stores.

--files-dir FILES_DIR

None

—

Where a survey queried on this machine keeps the catalogue it downloads – SDSS specObj, the 2MASS extended source catalogue – as one Parquet file per table. Downloaded once and shared by dry and real runs; only –overwrite-cache fetches it again, and –prune-stores never deletes it. The Legacy Survey sweeps downloaded from NERSC, converted, and their position index, are kept here too, under sweep/. Defaults to a “files” directory under –output.

--brick-cache-size BRICK_CACHE_SIZE

200.0

—

Disk budget, in GiB, of the Legacy Survey catalogue files kept under –files-dir: each sweep downloaded from NERSC and converted to Parquet. Past it files are evicted least recently used, and one needed again is downloaded again. A cell at the default order is a 1.83 degree pixel and selects a handful of the 5-degree sweeps, so leave room for the sweeps the cells around it reach too. Default: 200.

--catalog-mode CATALOG_MODE

materialise

materialise, view

What target_catalog is. “materialise” (the default) writes every column of every row into target_catalog.lance – a third physical copy of values the stores already hold, and the one a reader can open knowing nothing about this pipeline. “view” writes target_catalog.view/ instead: the query that rebuilds the catalogue from the stores, beside the only thing that cannot be rebuilt – what the cleaning decided, which is the deduplication survivors, the field of view and the split labels. It costs a join when the catalogue is read and saves the copy. It cannot be combined with –prune-stores, which would delete what the query reads.

--prune-stores

false

—

Delete the stores this run read once target_catalog.lance and targets_report.yaml are written, to reclaim their disk. The next run fetches every cell again, so leave this off while widening –dec-range step by step.

--scratch-dir SCRATCH_DIR

None

—

Where DuckDB spills and the phases put their intermediate tables. Wiped at the start and end of every phase that uses it, so nothing here survives the run – this is the opposite of –store-dir. Defaults to sitting beside each artifact. Point it at a large disk: the deduplication copies every row into each neighbouring sky tile and DuckDB spills its sorts here too. The nersc provider also downloads and converts each Legacy Survey sweep here before it enters –files-dir, so where the output is on NFS this wants to be a local disk.

--plan PLAN

None

—

Write the execution plan to this YAML file and exit without running. Constructs no provider, so it never logs in.

--dry-run

false

—

Run the whole graph against a small slice of every source, writing to /dry_run so it cannot be mistaken for a real catalogue.

--dry-run-rows DRY_RUN_ROWS

10000

—

Rows a dry run caps each extraction at. Default: 10000.

--strict

false

—

Abort the run if a crossmatch fails after its retries. By default a failed archive is recorded and skipped, and the run goes on to build the catalogue without that survey. Use this when an incomplete catalogue is not worth having.

--retry-failed RETRY_FAILED

none

none, band, all

Fetch again the sky cells an earlier run recorded as failed. Bare, or as “band”, it retries the failures inside this run’s –ra-range and –dec-range. As “all” it retries every failure ever ledgered, wherever in the sky it is – a cell is a global identifier, so a failure recorded by one run is retryable by any other, and those cells are stored but do not join this run’s catalogue. “all” is opt-in because widening the bare flag to mean it would make a narrow run drag in the whole sky’s backlog. Without the flag a failed cell stays out of the catalogue and the plan lists it, so one bad patch of an archive does not cost a rerun of everything around it.

--dec-range DEC_MIN DEC_MAX

None

—

Restrict every extraction to this declination band, in degrees. The way to try a real run at a size worth waiting for: unlike –dry-run, a band is a coherent piece of sky that the photometry and the spectroscopy both cover, so the joins downstream actually match. Combine with –ra-range for a box. Default: the whole sky.

--ra-range RA_MIN RA_MAX

None

—

Restrict every extraction to this right ascension wedge, in degrees. RA_MIN greater than RA_MAX is a wedge across RA 0, so “–ra-range 350 10” is the twenty degrees around it. Cells are HEALPix pixels bounded in both axes, so a run over a box reuses every cell an earlier run fetched and a later, wider run fetches only what it lacks – in either axis. Default: the whole circle.

--xmatch-radius XMATCH_RADIUS

None

—

One radius for every match: a spectrum belongs to a photometric object within it, and every crossmatch uses it in place of its survey’s own crossmatch.radius. A bare number is arcsec. Default: each survey’s own radius, and 1.0 arcsec for the spectrum-to-photometry match, the rescue and a survey with no crossmatch section.

--hle

false

—

Size every cutout with the half-light-ellipse method alone: the half-light radius times the circle correction factor of the r magnitude is the semi-major axis of the ellipse that ls11_shape_e1 and ls11_shape_e2 describe (axis ratio (1-e)/(1+e)), and the larger side of its bounding box is the catalogue’s fov. By default the ellipse form is used, and the circle form where the ellipse is missing. Either way a row with a missing measurement is left out of the catalogue, and a row whose size is zero is kept with an empty fov (mosaics-cutout gives it its default field of view).

--dedup-radius DEDUP_RADIUS

10.0 arcsec

—

Radius the production phase treats two rows as the same object at. A bare number is arcsec. Default: 10.0 arcsec.

--split-seed SPLIT_SEED

20260902

—

Seed the split. It orders each stratum by hash(row_id, seed) and sets the two lattice phases that dither the tier boundaries and the label interleave, so every split column is a pure function of the row and this number – reproducible across machines and thread counts. Change it only to draw a genuinely independent split of the same data. Default: 20260902.

--split-sizes COLUMN=SIZE

['phot_split_1pm=0.001', 'phot_split_1pc=0.01', 'phot_split_10pc=0.1', 'phot_split=1.0']

—

The nested tiers, smallest first, as column=size. A size at or below 1 is a share of the catalogue; anything above 1 is an absolute row count, which is the honest option for a catalogue small enough that one per mille is a smoke test. The subsets nest and a row keeps the same train/val/test label in every tier it belongs to, so scaling up adds data instead of swapping it. Default: phot_split_1pm=0.001 phot_split_1pc=0.01 phot_split_10pc=0.1 phot_split=1.0.

--split-ratios LABEL=PPM

['f=800000', 'v=100000', 't=100000']

—

Train/validation/test labels and their shares in parts per million, which must sum to 1000000. Default: f=800000 v=100000 t=100000.

--split-bins SPLIT_BINS

20

—

Quantile bins per continuous stratifier. Rows with no finite value get a bin of their own on top of these. Default: 20.

--split-stratifiers COLUMN

['ls11_mag_r', 'z']

—

Continuous columns whose joint distribution every tier preserves. Default: ls11_mag_r z.

--split-categoricals COLUMN

['has_spec']

—

Boolean columns that are a further axis of the same stratum grid. In the grid rather than constrained afterwards: two sequential constraints fight, one joint grid satisfies both. Default: has_spec.

--precedence COLUMN:ORDER

['has_spec:desc', 'ls11_mag_r:asc', 'ls11_mag_r_err:asc']

—

Which row survives a duplicate group, most important criterion first, as column:asc or column:desc. Nulls always sort last, so a row missing the criterion never beats one that has it. Default: has_spec:desc ls11_mag_r:asc ls11_mag_r_err:asc.

--proxy PROXY

None

—

Proxy URL, e.g. http://127.0.0.1:8888 to route through a mosaics proxy pool. HTTPS_PROXY is honoured when this is omitted.

--max-per-origin MAX_PER_ORIGIN

3

—

In-flight requests per host per source IP, which is what an archive actually throttles on. Behind a proxy pool the real ceiling is this times the number of connected workers, read from –proxy-stats-url. Default: 3.

--retries RETRIES

5

—

Attempts per request. Only transient failures consume attempts; a 404 fails immediately. Default: 5.

--timeout TIMEOUT

60.0

—

Per-request timeout in seconds. Default: 60.0.

--proxy-stats-url URL

None

—

URL of a mosaics proxy stats endpoint, e.g. http://127.0.0.1:8889/stats. Read once at startup to learn how many workers are connected, which is what turns –max-per-origin into the real per-host ceiling, and polled per batch for the telemetry panel when –wandb is on. A proxy that cannot be reached is treated as a single source IP.

--wandb

false

—

Publish step states, timings, the targets report and the catalogue summary to Weights & Biases. Best-effort: a W&B outage never aborts or slows the run, and with this off no wandb import is attempted at all.

--wandb-project WANDB_PROJECT

None

—

W&B project. Default: whatever WANDB_PROJECT says.

--wandb-entity WANDB_ENTITY

None

—

W&B entity. Default: whatever WANDB_ENTITY says.

--wandb-name WANDB_NAME

None

—

W&B run name. Default: derived from the output directory name.

--wandb-upload-catalog

false

—

Upload the catalogue directory itself as the “catalog” artifact, which can be very large. Without this flag it is recorded by reference only.

--workers, -j WORKERS

4

—

Batches or chunks in flight inside one step. Several steps run at once as well (see –steps-per-source), so the requests in flight against one archive are the product of the two. Default: 4.

--steps-per-source STEPS_PER_SOURCE

2

—

Steps talking to the same archive that may run at once. Steps on different archives never wait for each other, so a HATS crossmatch runs beside an Astro Data Lab one. Each step fans out by –workers itself, so the requests in flight against one archive are the product of the two. Default: 2.

--cell-order CELL_ORDER

None

—

NESTED HEALPix order the sky is cut into work units at. Each step up quarters a cell: order 4 is 3072 cells of 13.4 deg2, order 5 is 12288 of 3.36 deg2, order 6 is 49152 of 0.84 deg2. A cell is one query, one ledger entry and one unit of resume, so a coarser order means fewer, larger requests and a crash costs more. It is part of every store fingerprint – cells of two orders are not the same work units – so changing it refetches everything. At most 13, past which a cell index no longer fits the int32 cell column. Default: 5, or 2 for a dry run.

--duckdb-memory DUCKDB_MEMORY

None

—

Memory the candidate join and the production phase may give DuckDB, in DuckDB’s spelling: 64GB, 512MiB. Past it DuckDB spills to –scratch-dir, and it runs one thread per 2 GiB of it, so a small limit makes those phases slower rather than failing them. Default: half of this machine’s physical memory.

--log-level LOG_LEVEL

INFO

DEBUG, INFO, WARNING, ERROR, CRITICAL

Logging verbosity, for every module at once. DEBUG adds the full text of each generated query. Default: INFO.

--status-interval STATUS_INTERVAL

30.0

—

Seconds between [PIPELINE STATUS] blocks, which say how many of the roughly thirty steps are done and which are in flight. A step can be silent for minutes, so this is what tells a quiet run from a stuck one. 0 turns them off. Default: 30.
