mosaics-cutout — Image Cutout Extraction¶

mosaics-cutout (uv run -m mosaics.cli.cutout) retrieves fixed-shape astronomical image stamps for a target table and writes them alongside the input catalogue columns into a Lance dataset.

Subcommands¶

  • full: Multi-survey, multi-band extraction driven by a survey definition entrypoint (--config, default defs/full.yaml), automatically routing each (survey, band) to the fastest enabled backend.

  • hips: Single-band or RGB colour cutouts from any HiPS survey (remote CDS hips2fits service by default, or local tile rendering with --local).

  • lsv: Multi-band cutouts from the Legacy Survey Viewer HTTP API (ls-dr10, ls-dr11, ps1, hsc-dr3, sdss, galex, unwise-neo11).

  • nersc: Legacy Survey cutouts rendered locally from cached NERSC brick coadds (dr9, dr10, dr11).

  • sia: Cutouts reprojected locally from an IVOA Simple Image Access (SIAP) service.

  • vsa: Cutouts reprojected locally from the WFAU VISTA Science Archive (vhs5, viking).

Examples¶

$ uv run -m mosaics.cli.cutout full -t test/objects_sample_1k.csv -o cutouts.lance --config defs/cutout.yaml --size 96 --fov-unit arcmin --plan
$ uv run -m mosaics.cli.cutout hips -t test/objects_sample_1k.csv -o ps1_g.lance --hips-id CDS/P/PanSTARRS/DR1/g --size 64 --fov-unit arcmin --local
$ uv run -m mosaics.cli.cutout lsv -t test/objects_sample_1k.csv -o lsv_grz.lance --layer ls-dr11 --bands grz --size 96
$ uv run -m mosaics.cli.cutout nersc -t test/objects_sample_1k.csv -o nersc_grz.lance --data-release dr11 --bands grz --size 96

Targets without a field of view¶

Every target needs a field of view (--fov-col, in --fov-unit) because the per-row FOV sets the pixel scale of its stamp. A target whose FOV is empty (null, NaN, or not above zero; the targets catalogue leaves it empty for a galaxy of size zero) gets the default instead of failing: --default-fov, in the unit of --fov-unit, or, when it is not given, the median of the valid FOV values of the target table. The run logs how many targets got it and which value; a table with no valid FOV at all needs --default-fov. See Field of view.

$ uv run -m mosaics.cli.cutout lsv -t catalogue.parquet -o lsv_grz.lance --layer ls-dr11 --bands grz --size 96 --fov-unit arcsec --default-fov 30

Command-line reference¶

Entry points: mosaics-cutout or uv run -m mosaics.cli.cutout

mosaics-cutout hips¶

Fetch server-side cutouts from a HiPS survey.

mosaics.cli.cutout hips [-h] --targets TARGETS [--ra-col RA_COLUMN]
                               [--dec-col DEC_COLUMN] [--fov-col FOV_COLUMN]
                               [--fov-unit FOV_UNIT] [--default-fov FOV]
                               [--id-col ID_COLUMN] [--limit LIMIT]
                               [--no-sort] --hips-id HIPS_ID [--url URL]
                               [--size SIZE] [--format {fits,jpg,png}]
                               [--projection {sin,tan,mol,ait,car,cea,stg}]
                               [--stretch {power,linear,sqrt,log,asinh}]
                               [--min-cut MIN_CUT] [--max-cut MAX_CUT]
                               [--cmap CMAP] [--local] [--no-mirrors]
                               [--render-workers RENDER_WORKERS]
                               [--tile-cache TILE_CACHE_SIZE] --output OUTPUT
                               [--dtype DTYPE] [--survey SURVEY]
                               [--pixel-unit {nanomaggy,ab_zeropoint,counts_per_s,unknown}]
                               [--zeropoint ZEROPOINT] [--filters FILTERS]
                               [--image-col IMAGE_COLUMN] [--resume]
                               [--no-stats] [--retry-failed] [--proxy PROXY]
                               [--max-per-origin MAX_PER_ORIGIN]
                               [--retries RETRIES] [--timeout TIMEOUT]
                               [--proxy-stats-url URL] [--cache-dir CACHE_DIR]
                               [--cache-size CACHE_SIZE] [--wandb]
                               [--wandb-project WANDB_PROJECT]

                               [--plan-sample N] [--batch-size BATCH_SIZE]
                               [--no-progress]
                               [--log-level {DEBUG,INFO,WARNING,ERROR,CRITICAL}]
                               [--status-interval STATUS_INTERVAL]

Seconds between [PIPELINE STATUS] blocks, which say how many batches are done and which backends are in flight. A backend can be silent for minutes behind a rate limit, so this is what tells a quiet run from a stuck one. 0 turns them off. Default: 30.
